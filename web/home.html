An infinite canvas that stays fast.

Velm is a whiteboard app written in Rust. It draws the canvas straight on the GPU and draws only what is actually on screen — so a board with a hundred thousand things on it costs the same per frame as a board with two hundred. This server puts your boards in a browser, on whatever machine you happen to be sitting at.

Measured, not claimed

Every figure below was measured on the machine named beside it, and is reproducible from this repository. None of them is a benchmark somebody remembered.

On a Mac — 8-core, 8 GB Apple Silicon, August 2026

Installed, and how many processes it runs 18.5 MB · 1
Memory with a 596-item board open, every item on screen 104 MB
Frame time, all 596 of those items drawn 9.96 ms · 100 fps
Frame time on a 100,000-item board, 233 items on screen 9.96 ms · 100 fps

100 fps is that display's refresh rate. It means no dropped frames, not a ceiling. The comparison that started the project, on the same machine: Miro installs 296 MB, runs fourteen processes, and holds 357 MB with a board open.

In a browser — Brave on an M2, a 1,306-item board

Cold start, to a drawn frame 155 ms
Steady-state frame time on a fitted board 9.4 ms
The client itself — WebAssembly, and what crosses the wire 4.6 MB · 681 KB

The board was served from a copy, not from the originals. Opening one is slower than the steady state and that is where the work is: every visible block of text is shaped and every auto-fitted sticky note is measured on the first few frames.

What you can do here

In this tab, on this server, without installing anything.

  • Open a board and move around it

    Pan and zoom with a mouse or a trackpad, pinch and drag on a touchscreen. The board is drawn on the GPU through WebGPU, the same renderer the Mac app uses.

  • Edit it

    Select, move, resize, restyle, delete, and type on the canvas. There is no Save button and no timer: every edit is pushed as it happens, and the board of record is this server's, so the tab holds a working copy and never the only copy.

  • Work on a Mac and a tablet at once

    Changes made in the desktop app appear in an open tab without a reload, and the other way round. Boards merge rather than overwrite.

  • Search a board, and take one out

    Find a word anywhere on the board you have open, and download that board as SVG or as CSV.

  • Bring a Miro board across

    Select a board in Miro, copy it, and paste it into the import box on your boards page. It arrives as a new board here — stickies, text, frames, connectors, link cards and your pen drawings, which no Miro API exposes at all.

And there is a Mac app

The desktop app is where Velm started and where it is fastest. It keeps its boards in a folder on your own machine: no account, no sync service, nothing sent anywhere. It is what reads a Miro .rtb backup, exports PNG and PDF, and carries a native menu bar.

macOS 11 or later, Apple Silicon. Every release is signed with an Apple Developer ID and notarized by Apple, so there is nothing to allow in System Settings. Intel Macs and Windows can be built from source; neither has a published binary and neither is tested.

What a browser cannot do

Three things this tab cannot do, said here rather than found out later.

  • Pictures export as placeholders

    An SVG downloaded here carries every item's geometry, style and words, but each picture comes out as an empty rectangle: the browser decodes an image straight to the graphics driver, so there are no bytes left for an exporter to write. The count comes back with the file, so you are told how many. CSV is unaffected. PNG and PDF are desktop only.

  • A .rtb backup cannot be attached here

    Miro's clipboard carries references to pictures rather than pictures, so a board pasted into this page arrives complete except for the image pixels, and says how many are missing. The full-resolution images live in a .rtb archive, which the Mac app reads.

  • Nothing here runs a program on your machine

    A browser tab has no subprocesses. Anything that would drive another program on your computer belongs to the desktop app, and that is structural rather than unfinished.

About signing in

Everybody who uses this server has their own account. Every board has one owner, and you see the boards you own plus any that have been shared with you. The first account made on a server owns the server, and can create the others.

An account decides who can open a board, not who is drawing on it at the same moment. There are no live cursors, no presence and no comments anywhere in Velm — on the Mac either. It is a single-player tool by choice.

Passwords are never stored. What is kept is an Argon2id hash, which is a deliberately slow one-way function — the stored value carries its own cost parameters, so the cost can be raised later without resetting anybody's password.
