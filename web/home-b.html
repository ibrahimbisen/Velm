An infinite canvas, written in Rust

A canvas that draws only what you're looking at.

That is the whole idea — and it is why a board with a hundred thousand things on it costs the same per frame as a board with two hundred. 18.5 MB installed. One process. Native on a Mac, live in a browser, and the server is yours.

Measured, not claimed

Frame cost scales with what is on screen, not with what exists.

Every figure below was taken on one machine — an 8-core, 8 GB Apple Silicon MacBook, in August 2026 — and is reproducible from this repository. None of them is a benchmark somebody remembered.

100fps A 596-item board, every item on screen 9.96 ms a frame, in 104 MB. 100 fps is that display's refresh rate — it means no dropped frames, not a ceiling.
100,000 Items on the board, 233 drawn The same 100 fps and the same 9.96 ms a frame, in 110 MB. The other 99,767 cost nothing, because nothing draws them.
18.5MB Installed, running as one process Measured with du -sk on the built app. Miro, on the same machine, installs 296 MB and runs fourteen processes.
Installed 296 MB 18.5MB
Memory with one board open 357 MB 104MB
Processes it runs 14 1

Miro is Electron, so one process badly undercounts it — its memory figure is the sum of all fourteen, with a board open, after both apps had settled. Not claimed: a frame-rate multiple over Miro. There is no honest way to measure another application's frame rate from outside it, so Velm's numbers are given on their own.

In this tab

The same renderer, on whatever machine you happen to be sitting at.

This server compiles the desktop app's own renderer to WebAssembly and draws your boards through WebGPU. There is nothing to install and nothing to sign up to that you have not already run yourself.

155ms

Cold start to a drawn frame, GPU handshake and board fetch included.

9.4ms

681KB

Open a board and move around it

Pan and zoom with a mouse or a trackpad; pinch and drag on a touchscreen. Both were driven through the page's own event listeners and measured, not assumed.

Edit it

Select, move, resize, restyle, delete and type on the canvas. There is no Save button and no timer: every edit pushes on the frame it happens, and the board of record is the server's — so the tab holds a working copy, never the only copy.

Work on a Mac and a tablet at once

An edit made in the desktop app appears in an open tab with no reload, and the other way round. Boards merge rather than overwrite.

Search it, and take it out

Find a word anywhere on the board you have open, and download that board as SVG or CSV.

Bring a Miro board across

Copy a board in Miro and paste it into the import box on your boards page. It arrives as a new board — stickies, text, frames, connectors, link cards, and your pen drawings, which no Miro API exposes at all.

Nobody is watching

There is no telemetry, no analytics and no third-party request on any page here. This one fetches nothing but your own server.

Pricing

There isn't any.

Velm is free and open source under MIT or Apache-2.0, at your option. You run the server, so there is nobody to bill you and nobody holding your boards.

No seats

Make as many accounts on your server as you like. Nothing counts them.

No trial

No account with us

There is no “us”. The only account is the one on the server you are reading this from.

The desktop app

Where Velm started, and where it is fastest.

The Mac app keeps its boards in a folder on your own machine — no account, no sync service, nothing sent anywhere. It is what reads a Miro .rtb backup, exports PNG and PDF, and carries a native menu bar.

macOS 11 or later, Apple Silicon. Every release is signed with an Apple Developer ID and notarized by Apple, so there is nothing to allow in System Settings. Intel Macs and Windows can be built from source; neither has a published binary and neither is tested.

Straight about it

Three things a browser tab cannot do.

Said here rather than found out later. None of them is unfinished work.

Pictures export as placeholders

An SVG downloaded here carries every item's geometry, style and words, but each picture comes out as an empty rectangle: a browser decodes an image straight to the graphics driver, so there are no bytes left for an exporter to write. The count comes back with the file, so you are told how many. CSV is unaffected. PNG and PDF are desktop only.

A .rtb backup cannot be attached here

Miro's clipboard carries references to pictures rather than pictures, so a board pasted into this page arrives complete except for the image pixels, and says how many are missing. The full-resolution images live in a .rtb archive, which the Mac app reads.

Nothing here runs a program on your machine

A browser tab has no subprocesses. Anything that would drive another program on your computer belongs to the desktop app, and that is structural rather than unfinished.

Signing in

One server, your accounts, no service in the middle.

What an account is

Everybody who uses this server has their own. Every board has one owner, and you see the boards you own plus any that have been shared with you. The first account made on a server owns the server, and can create the others.

What it is not

It decides who can open a board, not who is drawing on it at the same moment. There are no live cursors, no presence and no comments anywhere in Velm — on the Mac either. It is a single-player tool by choice.

What happens to a password

It is never stored. What is kept is an Argon2id hash, a deliberately slow one-way function; the stored value carries its own cost parameters, so the cost can be raised later without resetting anybody's password.
